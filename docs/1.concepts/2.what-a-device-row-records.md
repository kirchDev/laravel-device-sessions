---
title: 'What a device row records'
description: 'Which facts about a browser the package stores, how much of the IP address survives, and how its timestamps move.'
---

A device row is meant to answer "where am I signed in?" for the user it belongs to — enough to recognise a browser, not enough to track one.

## How it works

Every resolution rewrites three fields from the current request, so the row always describes the browser as it was last seen:

- **`name`** — a readable label such as "Chrome on Windows", set once when the row is created and renamable by the user afterwards.
- **`os_family`** and **`user_agent`** — the detected OS family and the raw user-agent string.
- **`ip_address`** — the address after `IpMasker` has run.

Two timestamps are written by the throttled touch in `TouchDeviceLastSeen`: at most once per `cache.last_seen_throttle` seconds per device, both `last_seen_at` and `last_used_at` move to now, and `DeviceTouched` fires. A remember-me login additionally stamps `last_used_at` on the **token** row it used, not on the device.

## Why it's built this way

**The IP is minimised before it is stored, not when it is shown.** The default masker zeroes the last IPv4 octet (`/24`) and keeps only the first 48 bits of an IPv6 address. `/48` rather than `/64` is deliberate: a `/64` is typically a single subscriber, so it would identify a household rather than a network. An application with stricter rules rebinds the `IpMasker` contract; one with looser rules cannot recover what was never stored.

**The user agent is stored as-is.** It is what makes the row recognisable, and it is what `DeviceNameResolver` and `OsFamilyDetector` read again if they are rebound later. Treat the column as personal data in a retention policy — the prune command removes it together with revoked rows.

**The package assumes no column on your users table.** A "last seen" on the user is a common want, but writing it from here would force a schema on every host. `DeviceTouched` fires only on a real, unthrottled write, so a listener that stamps `users.last_seen_at` costs one query per device per throttle window rather than one per request.
