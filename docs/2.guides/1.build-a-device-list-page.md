---
title: 'Build a device list page'
description: 'Show a user where they are signed in, and let them rename a device, revoke one, or sign out everywhere else.'
---

The package ships no routes and no views — the actions return models, and the page is yours. What it does not decide for you is which of its operations ends a session and which only ends remember-me, so this guide wires both deliberately ([why they differ](/concepts/how-a-device-is-bound)).

## Steps

1. **Put the page behind the tracking middleware.** `track.device` is what sets the `current_device_id` attribute, so a page outside it cannot tell which row is "this device". Add `password.confirm` to the destructive routes and `auth.session` wherever "sign out everywhere else" has to take effect:

   ```php
   Route::middleware(['auth', 'auth.session', 'track.device'])->group(function () {
       Route::get('/devices', [DeviceController::class, 'index']);
       Route::patch('/devices/{device}', [DeviceController::class, 'rename']);
       Route::middleware('password.confirm')->group(function () {
           Route::delete('/devices/{device}', [DeviceController::class, 'revoke']);
           Route::post('/devices/sign-out-others', [DeviceController::class, 'signOutOthers']);
       });
   });
   ```

2. **List the devices and flag the current one.** `ListUserDevices` returns the active rows, most recently seen first; the "this device" flag is a comparison you make:

   ```php
   public function index(Request $request, ListUserDevices $devices)
   {
       $currentId = $request->user()->currentDeviceId($request);

       return view('devices.index', [
           'devices' => $devices->execute($request->user())
               ->map(fn ($device) => [
                   'id' => $device->getKey(),
                   'name' => $device->name,
                   'ip' => $device->ip_address,
                   'last_seen' => $device->last_seen_at,
                   'current' => (string) $device->getKey() === $currentId,
               ]),
       ]);
   }
   ```

3. **Rename through the action, not the model.** `UpdateUserDeviceName` returns `null` for a row the user does not own or that is revoked, which is the ownership check a route-model binding would otherwise skip.

4. **Revoke one device — and decide what that means for its session.** `RevokeUserDevice` ends that browser's remember-me login; an open session there carries on and reappears as a new row on its next request. A device row carries no session id, so the package cannot end that one session for you: either say on the page that the browser stays signed in until its session ends, or offer step 5 as the way to sign it out now. For the current device, offer an ordinary logout rather than a revoke.

5. **Sign out everywhere else through Laravel.** Call `Auth::logoutOtherDevices($request->input('password'))`. It invalidates the other sessions (through `auth.session`) and fires `OtherDeviceLogout`, which the package answers by revoking every other device. Do not call `RevokeOtherUserDevices` as well — unless `device-sessions.events.enabled` or `events.revoke_other_devices_on_other_device_logout` is switched off, in which case it is yours to call.

## Checklist

- [ ] The page and its actions run behind `track.device`, so the current device is known.
- [ ] Revoke and sign-out-others sit behind `password.confirm`.
- [ ] Routes that must honour "sign out everywhere else" carry `auth.session`.
- [ ] Rename and revoke go through the actions, which check ownership.
- [ ] The page says what revoking one device ends, or points to sign-out-others for ending sessions now.
- [ ] The current device is offered a logout, not a revoke.
